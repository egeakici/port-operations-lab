# Step 11 evaluation tooling, evidence NOT_RUN

The owner-manual runner checks exact source/config/approval digest, all declared
training seeds, immutable validation-selection receipts, trained-checkpoint
labels/hashes and train/validation/test physical separation before test inference.
No checkpoint is substituted from Project03. Every scenario-arm result retains
status, workload-validity, null failed makespan, runtime, source/model/input hashes
and a candidate schedule. Optional CP cells keep dependency/unsupported/solver
statuses distinct and expose finite-model bounds, never continuous global claims.

Cells are staged then renamed with a hash COMMIT. Resume verifies the original
plan and each committed cell, never overwriting prior successes, failures or
partial directories. The completion record lists all expected cells. Analysis
rejects duplicates/corruption, aggregates predeclared PPO seeds within scenario,
reports conditional complete-pair quality together with unconditional failures,
paired percent denominator, bootstrap intervals and worst/sign counts. Holm is
available for an approved p-value family; raw intervals are not simultaneous.

No actual training/held-out campaign exists. Empty report generation states
SCIENTIFIC_EVIDENCE_NOT_YET_RUN with zero trained models/runs; fixture rows are
labelled FIXTURE_ONLY_NOT_SCIENTIFIC. Code readiness does not establish adequate
sample size, superiority or final scientific closure. Full manual trainer and
held-out loop execution remain untested until separate authorization/locked inputs.

Existing-record report rendering includes manifest reference, actual status/failure
counts and approved paired-analysis settings/results. Standalone Matplotlib
runtime/quality points and paired confidence-interval figures require actual
recorded values; empty inputs reject rather than inventing a plot. Whole-episode
runtime axes are explicitly distinct from policy-only latency. Synthetic chart
tests establish rendering logic only, never scientific effects.
